# RDS — свой сервер RustDesk с панелью управления

Self-hosted сервер для [RustDesk](https://rustdesk.com) (ID-сервер + ретранслятор) и веб-панель для администратора парка ПК.
Проект не связан с командой RustDesk.

## Что умеет

- **Свои установщики клиентов** — Windows (.exe), macOS (.dmg), Linux (.deb/скрипт) с уже зашитыми адресом сервера и ключом; собираются панелью из последнего релиза RustDesk.
- **Список ПК** — онлайн/офлайн, локальный и внешний IP, пароль постоянного доступа, группы, заметки, подключение в один клик.
- **Агент на ПК** (Windows / Linux / macOS) — инвентаризация (CPU, RAM, диски, GPU, принтеры, сканеры, ПО, антивирус, активация), команды из панели: обновить RustDesk, перезагрузить/выключить с предупреждением, установить/удалить ПО из каталога.
- **Пользователи и права** — шаблоны прав (наблюдатель, оператор, техник, администратор и свои), права действуют только на ПК своих групп.
- **Вход через Active Directory / LDAP** — сопоставление «группа AD → группы ПК + шаблон прав», при желании вход по одобрению администратора.
- **Безопасность** — 2FA (TOTP, работает без интернета, с подстройкой под уход часов), подтверждение опасных действий кодом 2FA, отзыв сессий, журнал действий администраторов, у каждого ПК свой ключ агента, CSP/HSTS.
- **Резервные копии базы** — расписание, срок хранения и лимит размера в панели; шифрование [age](https://age-encryption.org); отправка в отдельные хранилища `rds-vault` по взаимному TLS (хранилище умеет только принять файл — удалить или перезаписать копии по сети нельзя).
- **hbbs с обменом ключами** — клиенты RustDesk 1.5+, вошедшие в аккаунт, требуют от ID-сервера TCP-обмен ключами (есть только в Pro). Здесь он добавлен патчем [`hbbs-kx/patch_kx.py`](hbbs-kx/patch_kx.py) к открытому rustdesk-server 1.1.16.

## Состав

| Сервис | Образ | Порты |
|---|---|---|
| `hbbs` | `scposs/rds-hbbs-kx` (rustdesk-server 1.1.16 + patch_kx) | 21115/tcp, 21116/tcp+udp, 21118/tcp |
| `hbbr` | тот же образ | 21117/tcp, 21119/tcp |
| `panel` | `scposs/rds-panel` (FastAPI) | 127.0.0.1:21114 → наружу через обратный прокси |
| `postgres`, `redis` | официальные | только 127.0.0.1 |

Все сервисы — `network_mode: host`, всё состояние — в `/opt/RDS/data`.

## Установка

Нужно: Linux-сервер с Docker и `docker compose`, публичный IP, одно-два DNS-имени
(например `rds.example.com` — ID-сервер и админка, `rd.example.com` — страница установки клиентов).

```sh
git clone https://github.com/scp-oss/rds.git /opt/RDS
cd /opt/RDS
RDS_HOST=rds.example.com CLIENT_HOST=rd.example.com ./install.sh
```

`install.sh` создаёт `.env` со случайными секретами, скачивает образы, запускает стек, ставит таймер копий базы
и показывает пароль первого администратора (один раз).

Затем:

1. **DNS:** A-запись `RDS_HOST` на сервер **без** прокси Cloudflare (клиенты ходят на 21115–21119 напрямую). `CLIENT_HOST` может быть за Cloudflare.
2. **Фаервол:** открыть 21115–21119/tcp, 21116/udp и 80/443 для обратного прокси.
3. **HTTPS:** обратный прокси на `127.0.0.1:21114` для обоих имён — пример для Caddy в [`deploy/Caddyfile.example`](deploy/Caddyfile.example). Для nginx: `proxy_pass http://127.0.0.1:21114;` с заголовками `Host`, `X-Forwarded-For`, `X-Forwarded-Proto`, `Upgrade`/`Connection`.
4. **Вход:** `https://RDS_HOST` → сменить пароль, включить 2FA (☰ → «Двухфакторная защита…»), затем включить «2FA обязательна для администраторов».
5. **Копии:** `apt install age`, в панели ☰ → «Резервные копии базы» → «Шифрование и хранилища…» → «Создать ключ шифрования» (закрытый ключ показывается один раз — сохраните его).

Клиенты ставятся со страницы `https://CLIENT_HOST`.

### Если 443 на сервере недоступен

Админку можно держать на другом порту (например, `https://rds.example.com:8444`, сертификат — через DNS-01),
а страницу установки и API для клиентов — через Cloudflare: `CLIENT_HOST` с оранжевым облаком и Origin Rule
«порт назначения 8444». В `.env`: `API_URL=https://CLIENT_HOST`. Агенты на уже установленных ПК сами
перепрописывают адрес API в RustDesk (не чаще раза в сутки); ПК без агента — переустановкой клиента.

## Обновление

```sh
cd /opt/RDS && git pull && ./install.sh
```

## Свои сборки образов

```sh
docker build -t rds-panel:local panel/
docker build -t rds-hbbs-kx:local hbbs-kx/      # Rust-сборка из исходников, ~5–10 мин
# в .env: PANEL_IMAGE=rds-panel:local  HBBS_IMAGE=rds-hbbs-kx:local
```

## Хранилище копий rds-vault

Отдельный маленький сервис для другого сервера/диска. Добавляется в панели (☰ → «Резервные копии базы» → «Шифрование и хранилища…» → раздел «Хранилища» → «Добавить»):
панель выпускает сертификаты и выдаёт команду установки. Хранилище принимает только зашифрованные копии и только от вашей панели (mTLS).

## Восстановление базы из копии

```sh
cd /opt/RDS
age -d -i key.txt data/backup/rds-ГГГГММДД-ЧЧММ.sql.gz.age | gunzip > /tmp/rds.sql   # без шифрования: gunzip -c файл.sql.gz
docker compose stop panel
docker exec -i rds-postgres psql -h 127.0.0.1 -p 5433 -U rds -d rds < /tmp/rds.sql
docker compose start panel && rm /tmp/rds.sql
```

## Безопасность

- `.env` и `data/` содержат секреты и ключ сервера — только root (`chmod 600 .env`, `700 data`), в git не попадают.
- `REG_TOKEN` попадает в публичные скрипты установки: он нужен только для первой регистрации ПК, дальше у каждого ПК свой ключ агента. После привязки всех ПК включите в панели строгий режим агентов (ПК без своего ключа перестанут получать команды).
- `data/id_ed25519` — закрытый ключ сервера: при переезде переносите его, тогда клиенты переподключатся сами.
- Сообщить об уязвимости: через GitHub Security Advisories этого репозитория.
